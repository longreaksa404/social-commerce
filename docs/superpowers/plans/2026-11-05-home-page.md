# Home Page for New Sellers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the logged-out start page (`/`) with a cinematic, luxury
landing page that wins new sellers: what Oak Order does, How it works on a
real 3D phone, the price, questions, a demo shop to try.

**Architecture:** A frontend-only page under `frontend/src/pages/home/`,
one component per section, texts in `messages/home.ts`. Real app
screenshots (WebP, committed) are the phone's screen. A CSS "still" phone
shows first; a three.js phone (its own lazy chunk) replaces it on capable
devices. The cinematic layer (opening sequence, grain, glows, scene dims)
is CSS plus two small hooks. A Python Playwright script,
`backend/marketing/home_check.py`, is the page's check suite, grown task by
task.

**Tech Stack:** React 19, TypeScript, Tailwind 4, React Router, TanStack
Query (prices), three.js (new), Pillow and Playwright (already in
`backend/.venv`).

**Spec:** `docs/superpowers/specs/2026-11-04-home-page-design.md`

## Global Constraints

- Phone first. No horizontal scroll at 360, 390, 414 and 1440 px wide, in Khmer and English.
- Every visible text is an `{ en, km }` pair in `frontend/src/i18n/messages/home.ts`; the founder checks the Khmer before it ships.
- Claims only from MARKETING_FACTS §3–§5 rows marked Live and the "you can say" column; nothing from §6 "Don't claim".
- Prices and trial days from `GET /plan/prices` (default `$9.99`, `$99`, `30`); "Save" = 12 × month − year.
- Demo shop: `DEMO_SHOP = 'zdpb5d'` → `/shop/zdpb5d`.
- `--color-champagne` (about `#d6bc8a`) is used on the home page only: step numbers, the price card's edge, the free-30-days line, small icons. It's an exception to the AGENTS.md UI rule "No decorative accent colours", approved by the founder 2026-11-04 and confirmed by options page section 1.
- `three` is imported only through a dynamic `import()` inside `pages/home/Phone3D.tsx`; it never reaches the entry chunk, the shop or the dashboard.
- One easing for everything: `cubic-bezier(0.16, 1, 0.3, 1)`.
- Opening sequence ≤ 1.6 s, once per visit (`sessionStorage` key `sc.home.intro`), never blocks a tap, ended by a tap or a scroll.
- Reduce motion: no opening sequence, no drifting glows, no wipes, no 3D (the still phone); the grain and vignette stay.
- Buttons at least 48 px tall. The page is navy in light and dark mode.
- Logged-in visitors still go straight to `/dashboard` (unchanged).
- No backend app change, no new env var, no new service. `backend/marketing/` stays out of the Docker image (it already is, `.dockerignore`).
- Live data: `shots.py` only reads the live demo shop. Nothing in this plan writes to the live site. Never print `.env` values.
- Every commit goes through the `finish-task` skill (AGENTS.md "When a task is done"). Don't push.

## Review Focus

1. **Long Khmer lines at 360 px**: the headline, buttons and price card wrap inside the screen, and no button text is cut (Task 3, `check_widths`).
2. **In-app browsers whose toolbar hides on scroll** (TikTok, Facebook): when the screen gets shorter mid-scroll, the pinned stage stays on the same step, without a jump (Task 4, `check_toolbar_resize`).
3. **Switching language on the page**: the phone's screen (still or 3D) changes to the other language's screenshots (Task 4 `check_lang_switch`, Task 6 `check_3d_lang`).
4. **Coming back with Back** from `/register` or the demo shop, mid-page: the same step shows and the opening sequence doesn't replay (Task 4 `check_back_nav`, Task 5 `check_intro_back`).
5. **The phone's WebGL lost** (an Android phone backgrounds the tab, a weak GPU): the still phone comes back, with no blank box (Task 6, `check_3d_context_lost`).

### Task 6: The 3D phone

**Files:**
- Create: `frontend/src/pages/home/phoneScene.ts`, `frontend/src/pages/home/Phone3D.tsx`
- Modify: `frontend/package.json` (`three`, devDependency `@types/three`), `frontend/src/pages/home/{Hero,HowItWorks}.tsx` (use `Phone3D`), `backend/marketing/home_check.py`, `docs/CODEBASE.md` (frontend libraries: `three`, home only, lazy; key files), `docs/04_STATUS.md`

**Interfaces:**
- Consumes: `PhoneStill`, `screenUrl`, `STEP_SCREENS`, `HowItWorks`'s stage (Task 4), `useIntro`.
- Produces:
  - `phoneScene.ts` (no React; imports `three`, `three/addons/geometries/RoundedBoxGeometry.js`, `three/addons/environments/RoomEnvironment.js`):
    ```ts
    export type Shot = 'hero' | 0 | 1 | 2 | 3
    export interface PhoneScene {
      setScreen(url: string): void      // load the texture, then cross-fade 0.4 s
      setShot(shot: Shot): void         // ease phone turn + camera to SHOTS[shot] over ~1 s
      setPointer(x: number, y: number): void  // -1..1 lean target; (0, 0) = rest
      setScroll(progress: number): void // 0..1, the hero's slow push-in
      sweep(): void                     // one light band across edge and glass
      setRunning(on: boolean): void     // draw loop on/off (off scrolled away / tab hidden)
      dispose(): void
    }
    export function createPhoneScene(canvas: HTMLCanvasElement, options: {
      screen: string; shot: Shot; finish: 'titanium' | 'navy' | 'black';
      onFirstFrame: () => void; onFail: () => void
    }): PhoneScene
    ```
    `SHOTS` (starting values, tuned by eye): `hero` turn y −0.35, x 0.08, camera z 6.2; `0` y −0.5, x 0.15 (low, wide), z 6.6; `1` y −0.15, z 5.2 (push in); `2` y 0.1, x −0.05, z 4.4 (close on the QR); `3` y 0.45, z 6.4 (pull back, turned the other way). The turn is clamped to ±0.6 rad, so the back never shows. Body: `RoundedBoxGeometry(3.9, 8.44, 0.36, 6, 0.42)` scaled to the screen's 390:844, `MeshPhysicalMaterial` metalness 1, roughness 0.32 (finish from pick 2), envMap from `PMREMGenerator(renderer).fromScene(new RoomEnvironment())`. Screen: a `PlaneGeometry` with `MeshBasicMaterial({ map, toneMapped: false })`, rounded with an alpha map. Two screen planes for the cross-fade. Glass: a `MeshPhysicalMaterial` plane with clearcoat and an animated highlight for `sweep()`. Island: a black capsule. Contact shadow: a radial-gradient sprite under the phone. `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, `alpha: true`. `onFail` fires on `webglcontextlost`, or when the first 60 frames average more than 40 ms. `onFirstFrame` fires after the first draw with the texture loaded.
  - `Phone3D({ screen, lang, shot, priority }: { screen: Screen; lang: Lang; shot: Shot; priority?: boolean })`: renders `PhoneStill` always, plus a `<canvas data-phone3d data-shot={shot} data-screen={url} aria-hidden>` over it when `canUse3D()`. It `import('./phoneScene.ts')` after mount (and after `useIntro()` is `done` or 300 ms, whichever comes first, so the intro's first frames aren't janky). The canvas fades in on `onFirstFrame`, while the still stays under it for layout. On `onFail` it disposes and removes the canvas. An `IntersectionObserver` and `visibilitychange` drive `setRunning`; `pointermove` on the hero drives `setPointer`; a `screen`/`lang` change → `setScreen`; a `shot` change → `setShot` + `sweep()`.
  - `canUse3D(): boolean`, exported from `Phone3D.tsx`: false if `reducedMotion()`; if a test `canvas.getContext('webgl2') ?? getContext('webgl')` is null; if `navigator.connection?.saveData`; if `navigator.deviceMemory` is defined and below 4; or if `navigator.hardwareConcurrency` is defined and below 4.
